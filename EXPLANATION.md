## 2026-08-31 — Task 4: IR build + validate

- **What changed:** Implemented `pipeline/ir_build.py` (skeleton scaffold + `--derive` mirror resync) and `pipeline/ir_validate.py` (read-only validator). Tests in `tests/test_ir_build.py` (8) and `tests/test_ir_validate.py` (21, one seeded violation per rule). No new dependencies. Contract 2 gained a top-level `figures:` inventory section (pre-freeze; see DECISIONS.md).
- **How it works:** `python -m pipeline.ir_build <run_dir>` writes `ir.yaml`: the Contract 2 skeleton pre-filled from `manifest.yaml` + `fetch_meta.yaml` (id, title, authors, year, source_kind, first repo candidate as `official_repo` status `stated`) and `figures/figures.yaml` (glob fallback for the PDF path, which writes no figures manifest). Every status leaf starts `unknown` and `implementation_notes.unknowns` is pre-derived, so a fresh or partially filled IR validates clean by construction; a static header comment carries the fill rules. Refuses to overwrite without `--force`. `--derive` regenerates assumptions/unknowns from statuses, preserving hand-written `basis` per field. `python -m pipeline.ir_validate <run_dir>` checks: section/key shape, status vocabulary, `stated`/`inferred` ⇒ non-empty `src`, component/equation/headline-result `src`, equation LaTeX balance (escape-aware braces + matched `\begin`/`\end`), diagram file existence, and the exact assumptions/unknowns mirror. Exit 0 clean, 1 with one finding per line, 2 operational. The status-leaf set is defined once (`ir_build.status_fields`) and imported by the validator — build and validate cannot drift. Validator never writes; manifest updates belong to the ingest skill (Task 5).
- **How it was verified:** `uv run pytest -q` → `75 passed, 6 deselected`. Real workspace: `ir_build runs/2106.09685` → pre-filled LoRA IR (metadata, microsoft/LoRA repo, 8 figures) → `ir_validate` → `ok`, exit 0. Deliberately broken IR (deleted `experiments`, `stated` lr without src, truncated equation latex) → 4 findings, exit 1, including the stale-mirror catch. `cavecrew-reviewer` pass on the diff: no issues. Test `ir.yaml` removed from the run workspace afterward.
- **Limitations / follow-ups:** "Parseable LaTeX" = balance checks, not a grammar — catches truncation/mangling, not semantic nonsense (the Task 5 auditor owns semantics). `--derive` rewrites `ir.yaml` and drops any inline comments Claude added mid-file (static header survives). `src` pointers are only checked non-empty — real provenance checking is the Task 5 `ir-auditor`'s job. Status-leaf set and the `figures:` section get revisited at the Task 5 quality gate before schema freeze.

## 2026-08-31 — Task 3: extract.py

- **What changed:** Implemented `pipeline/extract.py` — `source/` → `paper.md` + `figures/` (+ `pages/` for PDF). Added PyMuPDF. Tests in `tests/test_extract.py` (offline unit + synthetic latex/pdf/html + network on the three papers).
- **How it works:** `extract(run_dir)` dispatches on `manifest.yaml` `source_kind`. LaTeX path strips comments/preamble, preserves the body verbatim (equations, tables, inline math as LaTeX), rewrites each `\includegraphics` to a stable `figures/figN.<ext>` and copies the asset, and records provenance + caption in `figures/figures.yaml`. A depth-aware `brace_arg` handles nested paths (`\iftoggle{hq}{A}{B}`); `resolve_asset` picks the first on-disk candidate. PDF path (PyMuPDF) extracts text + embedded images + 150 dpi page renders; HTML path (stdlib `HTMLParser`) extracts text + `<img>` assets. Full mechanism in ARCHITECTURE.md → "Extract pipeline".
- **How it was verified:**
  - `uv run pytest -q` → **44 passed, 6 deselected** (offline; includes synthetic latex/pdf/html round-trips and the traversal-rejection test).
  - `uv run pytest -q -m network` (extract) → **3 passed** — LoRA (4 eq, 8 fig), DDPM (16 eq, 18 fig), Grokking (0 eq, 11 fig).
  - Human spot-check on persisted `runs/`: DDPM `paper.md` contains all 16 `\begin{align}` verbatim; `\includegraphics` rewritten to `figures/fig1.png`/`fig2.png`; `figures.yaml` records original path + caption; `paper.md` starts at the title (preamble/comments gone); paper.md sizes 30–95 KB.
- **Security (Phase E):** Same untrusted-content boundary as Task 2. `_within()` blocks `../`/symlink escape so a crafted `\includegraphics{../../secret.png}` or HTML `<img src>` cannot copy files out of `source/`; regression test `test_resolve_asset_rejects_traversal`.
- **Limitations / follow-ups:** `figures/figN` keeps the original extension — LoRA figures are `.pdf`, not raster; a skill needing a viewable diagram must rasterize on demand (Task 5/7 follow-up). The `caption` field in `figures.yaml` strips inline-math macros (`\times`) for readability — a convenience only; the faithful caption is verbatim in `paper.md`. HTML/PDF paths are unit-tested on synthetic inputs but not on a real paper (all three test papers are LaTeX). The `network` extract test re-fetches, so running the full `-m network` suite (6 arXiv hits) can rate-limit; space runs out if it flakes.

## 2026-08-31 — Task 2: fetch.py + workspace.py

- **What changed:** Implemented `pipeline/workspace.py` (create run dir, build/read/write `manifest.yaml` per Contract 3) and `pipeline/fetch.py` (resolve any supported input → download source into `runs/<slug>/` → write manifest + `fetch_meta.yaml`). Added `PyYAML`. Added a `network` pytest marker, deselected by default. Tests: `tests/test_workspace.py`, `tests/test_fetch.py` (offline unit + network integration).
- **How it works:** `resolve_input` classifies the input (arXiv id/URL new+old id forms, direct PDF URL, local pdf/tex/txt) or raises `FetchError`. arXiv path downloads the e-print tarball, unpacks it safely, finds the main `.tex`, and flattens `\input`/`\include` into `main.flattened.tex`; if the e-print is a PDF it falls back to `/html/{id}`, else saves the PDF. Metadata (title/authors/year/abstract/official-repo candidates) comes from the export API Atom feed. `source_kind` (`latex`/`html`/`pdf`) is recorded in the manifest. Full flow in ARCHITECTURE.md → "Fetch pipeline".
- **How it was verified:**
  - `uv run pytest -q` → **31 passed, 3 deselected** (offline).
  - `uv run pytest -q -m network` → **3 passed** — LoRA (2106.09685), DDPM (2006.11239), Grokking (2201.02177) all fetch via e-print with figure assets present.
  - Manual CLI: `python -m pipeline.fetch <id>` for all three produced valid workspaces (`source_kind: latex`, flattened tex, 8/18/11 figure assets, official repos microsoft/LoRA, hojonathanho/diffusion, openai/grok). Garbage input → `fetch failed: unrecognized input …`, exit 2 (no stack trace).
  - `security-review` + `cavecrew-reviewer` run on the diff; all findings fixed and covered by regression tests (below).
- **Security findings fixed (Phase E):**
  1. **Path traversal (HIGH):** malicious e-print `\input{/etc/passwd}` / `../` read local files into the flattened source. Fixed with a source-tree containment check; test `test_flatten_rejects_out_of_tree_input`.
  2. **`file://`/SSRF (MED):** HTML `<img src>` could smuggle `file://` or internal hosts into `_download`. Fixed by restricting asset fetches to `http(s)` on `arxiv.org`; test `test_html_assets_reject_nonarxiv_and_filescheme`.
  3. **Python floor (correctness/security):** `tarfile` `filter="data"` needs ≥3.11.5; bumped `requires-python` so the tar guard is never silently disabled.
  4. XML `ParseError` and `None` author entries wrapped/filtered for explicit failure.
- **Limitations / follow-ups:** HTML and PDF acquisition paths run only when e-print is unavailable; not exercised by the three (all-LaTeX) test papers — `extract.py` (Task 3) is where the PDF/HTML branches get real coverage. `official_repo` is captured as *candidates* in `fetch_meta.yaml`; the IR promotes one to `official_repo` in Task 4/5. No `defusedxml` dep (DTD-reject guard is sufficient for the single arXiv feed).
